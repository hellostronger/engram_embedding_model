# Engram 原论文思路解析

> DeepSeek《**Conditional Memory via Scalable Lookup**》
> arXiv:2601.07372 · 代码 `deepseek-ai/Engram`
>
> 本文档解释**原论文在解决什么问题、怎么解决、为什么这么设计**，并配合
> `docs/figures/` 下的架构图阅读。最后落到"我们复用了什么、改了什么"。

---

## 0. 一句话

**Transformer 缺一个"查表"原语。** 它被迫用几十层 attention + FFN 的算力，
去**重新模拟**一个本来 O(1) 就能查到的静态事实。Engram 给它加上这个原语，
把静态知识从动态计算里拆出去。

---

## 1. 问题：Primitive 缺失

论文的出发点不是"再加一个记忆模块"，而是一个更底层的观察：

> *Simulating retrieval through computation* —— 用计算去模拟检索，
> 是 Transformer 的结构性浪费。

看 [`engram_insight.svg`](figures/engram_insight.svg) 的左右对比：

| | 现状（无查原语） | Engram（有查原语） |
|---|---|---|
| 输入含多 token 实体<br>（如「黛安娜，威尔士王妃」） | L1–2 拼出"威尔士=英国"<br>L3–4 拼出"王妃"头衔<br>L5 FFN 拼出全名<br>L6 FFN 补生平事实 | L2 一次哈希查表<br>门控 α≈1 确认命中<br>直接拿到静态表示 |
| 代价 | **消耗 6 层深度**重建一个静态查找表 | O(1) 查表，几乎零深度 |
| 后果 | 有效深度被"记忆劳动"挤占 | L3…L12 **全部留给组合推理** |

论文给出的**实证**（CKA 表征对齐）：Engram 模型的 L5 表征
≈ 基线模型的 **L12**。也就是说，同样层数下它的**有效深度接近翻倍**。

这解释了一个反直觉的实验结果——**通用推理（BBH +5.0、ARC-C +3.7）
比知识检索（MMLU +3.4）受益还大**。因为省下来的深度，正好被用去做推理。

## 2. 核心机制：suffix N-gram 的确定性查表

完整模块见 [`engram_arch.svg`](figures/engram_arch.svg)。数据流分两条路：

### 2.1 检索路（左，蓝色）

```
输入 x_1..x_T
   │  ① Tokenizer 压缩  P: V → V'
   │     NFKC / NFD / 去音标 / 小写 / 空白折叠
   │  ② 提取 suffix N-gram
   │     g₂ = (x'_{t-1}, x'_{t})        g₃ = (x'_{t-2}, x'_{t-1}, x'_{t})
   │  ③ 多头乘法-XOR 哈希
   │     z_{t,n,k} = φ(g) mod M_{n,k}    M 为互异素数
   ▼
E₂,₁  E₂,₂  E₃,₁  E₃,₂ … E_{N,K}   ← (N−1)·K 张素数表
   │  ④ 拼接
   ▼
e_t ∈ ℝ^d
```

**为什么是 suffix（后缀）而不是全窗口**：t 时刻只依赖
`x'_{t-n+1} … x'_{t}`，这样是**因果**的，能直接插进 decoder-only
残差流，不泄露未来信息。

**为什么多头 + 素数取模**：单头哈希碰撞率高。K 个独立哈希头、
每张表用不同素数大小，碰撞被独立化——一个头撞了，其他头还对。
这是把"查表"做成**可学习的**而不是死查的关键一步。

### 2.2 动态路（右，绿色）

backbone 前 l 层照常跑 attention + FFN/MoE，产出上下文隐状态 `h_t`。
`h_t` **已经聚合了全局上下文**，所以它当 Query 正合适——
这正是后面门控能判断"该不该信这条记忆"的依据。

### 2.3 融合（黄色区）

```
k_t = W_K e_t        记忆 → Key   （分支专属 W_K⁽ᵐ⁾）
v_t = W_V e_t        记忆 → Value  （跨分支共享，无 bias）
α_t = σ( RMSNorm(h_t)ᵀ · RMSNorm(k_t) / √d )
ỹ_t = α_t · v_t
```

三处细节值得记：

1. **`W_V` 无 bias** —— 这是我们的 NULL 惰性保证的来源：
   空记忆 ⇒ `v_t = 0` ⇒ 注入恰好为 0，删干净了就是真删干净。
2. **`W_K` 分支专属、`W_V` 共享** —— 让每个分支有自己的"触发指纹"，
   但输出空间统一。
3. **门控是安全阀** —— 静态记忆没有上下文适配能力，靠 α 消解
   多义与哈希碰撞。实测高激活于**多 token 实体、成语、专业术语**，
   论文原文举的例子是「安然无恙」这类模板短语。

### 2.4 卷积 + 残差（底部）

```
Y = SiLU(Conv1D(RMSNorm(ỹ))) + ỹ      kernel=4, dilation=N, 零初始化
H_t ← H_t + Y_t
```

深度因果卷积用于**拓宽感受野**——把单点记忆扩展成局部上下文片段。
**零初始化**保证训练起点 = 无记忆（identity）。

论文 §4.1 的重要性排序（消融）：
**多分支集成 > 门控 > tokenizer 压缩 > 卷积**
——即卷积是"锦上添花"，前三个才是命根子。

## 3. 为什么"每层都注"是错的：插入点结论

`engram_arch.svg` 右侧标注的插入层来自消融（12 层模型）：

- **单点注入 Layer 2 最优**，往深走效果递减
- **拆成 Layer 2 + Layer 6 两个小模块**，比单点大模块更好
  （早干预 + 后期强上下文门控）

机制解释：记忆越早注入，后续层越多，能把它精炼得越充分；
放最后一层则注入后**直接进 pooling，没有任何后续 block 精炼**。

> ⚠️ **对我们的警告**：我们的部署目标 `bge-small-zh-v1.5` 只有 **4 层**，
> 当前配置 `layer_ids=[1,3]` 把第二个模块放在了**最后一层**，
> 违反了上面的机制假设。建议改为 `layer_ids=[1,2]`。
> （详见 `docs/EXPERIMENTS.md`）

## 4. 稀疏性分配：U 形定标律

固定总参数 `P_tot` 与激活参数 `P_act`，怎么在
**MoE 专家**（条件计算）与 **Engram 记忆**（条件存储）之间切分？

定义 `ρ = MoE 专家分得的稀疏参数占比`，见 [`engram_scaling.svg`](figures/engram_scaling.svg)：

| 配置 | 验证损失 |
|---|---|
| **纯 MoE**（ρ = 100%） | 1.7248 —— **次优点** |
| **最优 ρ ≈ 75–80%** | **1.7109** |
| ρ → 0（记忆主导） | 损失回升 —— 丢掉条件计算 |

**结论：不存在"记忆越多越好"。** 让出 20–25% 稀疏参数给记忆反而更好。

两条曲线的形状：
- **左图（U 形）**：两端都差，中间有唯一最优。ρ=0 时没有组合推理能力，
  ρ=1 时静态模式"无家可归"。
- **右图（对数线性）**：记忆槽位数 M 加到 **≈13B 参数仍未饱和**——
  这是**严格幂律**，加表不加 FLOPs（每 token 激活槽位数恒定）。

> 这正是我们做垂域 Embedding 的立足点：**长尾术语容量只吃内存，
> 不拖慢编码吞吐**。但论文也提醒——Adam 更新会遍历全表，
> 所以"加表免费"只对**推理**成立，对**训练显存**不成立。

## 5. 系统效率：确定性寻址才能 offload

这是 Engram 相对 MoE 的**结构性优势**，也是我们方案能"存储与计算分离"的根据：

| | MoE（条件计算） | Engram（条件存储） |
|---|---|---|
| 寻址方式 | 动态路由，依赖输入内容 | **确定性哈希，只依赖 token id** |
| 能否预取 | ✗ 要先算才知道 | ✓ **可预取** |
| CPU offload | 不行 | 可行 |

实测（H800，100B 表全量 CPU offload）：**吞吐仅 −2.8%**。

查表成本 ∝ 激活槽位数，**与表总大小无关**；且天然不占 attention 预算、
不需要额外 KV cache——把局部依赖外包给查表，attention 专注全局。

---

## 6. 记忆消融：什么时候"记忆"是必需的

论文把记忆整块拿掉后测掉点：

| 任务类型 | 掉到 |
|---|---|
| **事实类** | **29–44%**（灾难性） |
| **阅读理解类** | 81–93%（轻度） |

说明：Engram 的记忆主要承载**离散事实**，阅读理解更多靠通用能力。
这直接支撑了我们做**垂域术语记忆**的方向——术语正是"离散事实"。

## 7. 我们复用了什么、改了什么

### 复用（Engram-faithful）
- suffix N-gram 因果提取
- 多头乘法-XOR 哈希 + 互异素数取模
- 上下文感知门控 `σ(RMSNorm(h)ᵀRMSNorm(W_K e)/√d)`
- 深度因果卷积，**零初始化**
- `W_V` 无 bias ⇒ 空记忆零注入
- 冻结 backbone，记忆表 5× 学习率、wd=0（论文 §4.1）
- 优先注入浅层（层 2）

### 扩展（我们的增量）
| | 原论文 | 我们 |
|---|---|---|
| 可寻址性 | 槽位由哈希决定，**不可寻址** | 新增 **Layer-A `PhraseRegistry`**，显式 `phrase→slot` 字典 |
| 增删改查 | 不支持 | O(1) CRUD + 墓碑删除 + free-list |
| 新词冷启动 | 需梯度训练 | **跨上下文共识 + 闭式 ridge 解**，零梯度 |
| 层数前提 | 12 层 | 4 层 → **插入点需重调** |

**为什么必须双层**：原表哈希槽位不可寻址，无法"改一条不动其它"，
运营写不进领域新词。Registry 层补上这个缺口，同时保留哈希层的大容量。
